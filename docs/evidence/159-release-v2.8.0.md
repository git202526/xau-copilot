## 1. 需求

用户原文：

> 现在判断偏空和继续买入等于接飞刀。出熔断，那么技术面转为中性的条件是什么？请在熔断提醒栏目下方列出空、中性、多的成立条件。并打✔和X表示出来单条是否满足。

原熔断条只说「等转为中性再恢复」，**没给门槛**。用户看到偏空、被要求暂停买入，却无法判断什么时候能恢复——这是一个无法验证的承诺。

## 2. 判定链（来自 `src/core/technical.js`，本次未改判定逻辑）

```
① 数据链：B.ok && !stale && indicators.ok        → 不满足即 degraded，dir=0
② 避险：C.mode !== "risk_off"（VIX 单日 > +20%）→ 不满足即 risk_off，dir=0
③ 加权得分 score = 多头权重 /（多头 + 空头）× 100（四舍五入）
   score ≥ 60 → 偏多 ；score ≤ 40 → 偏空 ；41–59 → 中性
```

前置任一条 ✗ 时 `dir` 恒为 0。这一点必须在界面上说明，否则用户会误以为「VIX 暴涨 = 中性」。

## 3. 交付内容

M4 熔断提醒条**下方**新增「技术面三档成立条件」，三档 × 三条：

| 档位 | 条件 |
|---|---|
| 偏空 | ① 数据链正常（源可用 · 未过期 · 指标就绪）② 无宏观避险拦截（VIX 单日 < +20%）③ 加权得分 ≤ 40 |
| 中性 | ① ② + 加权得分 41 – 59 |
| 偏多 | ① ② + 加权得分 ≥ 60 |

- 每条右侧给出**当前值**与**差多少分**：`当前 13，差 28 分`
- 底部换算成可执行量：`转中性还差：需净 +28 分，≈ 2.21 个指标翻向（权重 1 计）由空翻多`
- 当前成立的档位整块高亮 + 「成立」字样；其余标「不成立」
- 降级 → 「已降级，本轮不出方向」；避险 → 「避险模式，方向判断暂停」（区分「缺数据」与「被拦截」）

## 6. 口径纪律

`src/core/ladder.js` 顶部写死了三条约束，并有用例守着：

1. `score` 只读 `technical.score`（不按 `weights` 重算）—— 用例 S2 故意给不自洽的 weights，重算必露馅
2. 档位只认 `technical.scenario` —— 用例 M6 守着
3. 阈值从 `resolveThresholds(cfg)` 取 —— 用例 S1 同时读 `technical.js` 源码核对 60/40

第四条是**自洽性**（S3 + B1）：`active` 档内所有条件必须全 ✔，非 active 档至少一条 ✗。这条保证界面不会出现「中性整块打勾但显示不成立」这种事。

v2.7.0 的档距漂移（190.7 vs 105）就是「两处各算一遍」的后果，这次从一开始就堵掉。

## 8. 已知边界

- **条件表随整页 60 秒刷新重画**，不跟 15 秒金价 tick 联动：得分由 8 个指标加权而来，15 秒重算会让三档结论抖动，反而更难看懂。
- **得分取整数**：`technical.js` 里 `Math.round`，所以 40.x 与 39.5 都可能落到 40。边界用例 B1 钉的是 40/41/59/60 四个整数点。
- **`weightsNeeded` 是近似值**：按「每 1 权重 = 100/total 分」线性折算，实际翻向还受 `total` 自身变化影响（某个指标从 ±1 变 0 会让 total 缩小）。量级正确，不必当精确解。
