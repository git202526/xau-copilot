## 2. 根因：不是算错，是口径没跟上

### 2.1 档距少算了两种模式

老应用 `gearBase()` 的档距是三步：锚点 `p1 = H×(1−起始跌幅%)` → 按模式取 `d` → 用终止跌幅夹一道 `capD`（**只压不拉**）。三种模式：

| 模式 | 公式 | 本例取值 |
|---|---|---|
| `alpha`（当前在用） | `d = α × ATR14` | 1.16 × 90.5 = 105 |
| `target` | `d = (p1 − T_eff) / frontCenter(w,k)` | 未启用 |
| `range` | `d = (终止−起始)/100 × H/(n−1)` | 若启用为 190.7 |

旧实现只会 `range`，对同一份配置得出 190.7，于是第 5 档 `4038.56 − 4×190.7 = 3275.9`。老应用是 `4038.56 − 4×105 = 3618.59`。

### 2.2 每档克重漏了两个扣减

```
预算   = TOTAL − 未标记档位持仓          ← 本例 400 − 328.8848 = 71.1152 克
计划   = 预算 × w_i / Σw                 ← 3.56 / 3.56 / 21.33 / 35.56 / 7.11 / 0
下沉   = 跌破档（现价 ≤ 档位价×0.99）的待补按权重挪给未失效档
```

现价 3874.69 时第 1、2 档（4038.56 / 3933.57）已跌破 → 池子 7.1115 克按 30:50:10 下沉 → **23.7051 / 39.5084 / 7.9017**。旧实现直接用 `TOTAL × wPct`，是「满仓分配」而不是「剩余可分配」，量级差 5 倍。

| 5 | 3,618.59 | 3,619.6 | 1.01 |
| 6 | 3,513.59 | 3,514.8 | 1.21 |

残余 0.03% 的来源已定位：ATR14 取的是老应用日线，而当日未收盘那根的 h/l 会被现价推进，ATR 在日内从 90.51 变到 90.30。**同一时刻两边算的是同一个数**，差在快照最多 10 分钟的时差。

## 7. 已知偏差（写在代码注释里，不是漏做）

1. **下沉滞回**：老应用「已失效」后要涨回 0.3% 才恢复（跨帧记忆）；本应用每次重算无状态，统一按 1% 判失效。只在 1% 临界带里可能差一档，方向不受影响。
2. **目标不可达**：老应用把档距置 0 并报错；本应用回退 α 排档并在卡面标「目标不可达，回退 α」，避免六档价格重合成一个数。
